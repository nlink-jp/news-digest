# news-digest

自分でフィードを収集し、読むべきものを判定して、それだけのダイジェストを作る
Claude Code Skill。

フィードをチャットに転送するだけだと 1 日 130〜180 件になり、結局だれも読まない。
このスキルは代わりに 3 つの区別を付ける。

- **見るべきか** — 事案の重大性と、自分との関係を**別々に**評価する
- **目新しいか** — すでに追いかけている継続案件（ストーリー）と突き合わせる
- **陳腐化していないか** — 「今日も流れてきたが新事実は無い」話題を名指しする

3 番目が肝で、これがあると**「読まなくてよかった理由」の記録**が残る。

## コードはここ、データは別

このリポジトリはエンジンだけを持つ。フィード一覧・関心プロファイル・記事コーパスは、
自分が所有する**私有のコーパスリポジトリ**に置く。何を見張っていて何を気にしているかを
記述したものであり、公開するたぐいのものではない。

```
news-digest (public)                  your-corpus (private)
  スキル・スクリプト・プロファイル        config/  data/  digests/
  サンプル・テスト                       .newsrc.toml
```

コーパス側にコードは 1 行も入らない。インストール済みのスキル 1 つで複数のコーパスを
回せる。両者の契約が `.newsrc.toml` で、config と schema の版・評価プロファイル・
ダイジェストの送り先を宣言する。スキルは対応していない版のコーパスに対して実行を拒否するので、
エンジンの更新がコーパスを黙って壊すことはない。

## プロファイル

エンジンはいかなる分野の知識も持たない。**プロファイル**が、評価軸・軸スコアを
読む優先度に変換する決定表・評価前に読む rubric・ダイジェストのレイアウトを供給する。

基底として 3 軸を同梱する。意図的にドメイン非依存にしてあり、根拠は
**参照フレームが直交している**ことにある。

| 軸 | 問い | フレーム |
|---|---|---|
| `novelty` | 既知の内容に何を足すか | 時間 |
| `significance` | 自分を除いて、どれだけ大きい話か | 世の中 |
| `relevance` | 自分にどれだけ直接触れるか | 自分 |

`security-news` は基底プロファイルを継承し、rubric・決定表・`interests.toml` の形だけを
上書きする。軸 id はプロファイル間の共有語彙なので、rubric を調整しても
蓄積済みのコーパスが自分自身と比較不能になることはない。

**エージェントは priority を書かない。** 軸を採点し、決定表はスクリプトが適用する。
違反できないルールは、強制する必要がない。

## インストール

[Releases](https://github.com/nlink-jp/news-digest/releases) から
`news-digest-vX.Y.Z.zip` をダウンロードし、登録する:

- **アプリから**（Claude Desktop / claude.ai / モバイル）— スキル設定
  （カスタマイズ → スキル）で zip を追加する。**この経路を推奨**。
  スキルの保存場所が変わっても影響を受けない。
- **Claude Code** — `unzip news-digest-vX.Y.Z.zip -d ~/.claude/skills/`。
  プロジェクト単位なら、プロジェクト内の `.claude/skills/` に展開する。

チェックアウトから:

```bash
make install
```

リリース zip をビルドして**それを**展開するので、手元で動かすものと
リリースが配るものが一致する。パッケージングの欠陥は利用者に届く前に
手元のインストールを壊す。`make install DEST=/path/to/skills` で別の場所へ、
`make uninstall` で削除。

## 使い方

```bash
/news-digest --repo ~/path/to/your-corpus
/news-digest --repo ~/path/to/your-corpus --since 2026-08-01 --dry-run
/news-digest --repo ~/path/to/your-corpus --source jpcert
```

| 引数 | 既定 | 意味 |
|---|---|---|
| `--repo <path>` | カレントディレクトリ | コーパスリポジトリ |
| `--since` / `--until` | 前日 00:00 / 現在 | 収集対象期間 |
| `--source <id>` | 全ソース | 対象ソースの限定（複数可） |
| `--dry-run` | — | 通知も commit もしない |
| `--no-post` / `--no-commit` | — | 個別に抑止 |

コピーして使えるコーパスの雛形が `news-digest/examples/corpus/` にある。
`news-digest/references/setting-up-a-corpus.md` はエージェントが一緒に実行できる
runbook で、関心・フィード・送り先を答えるのは利用者、残りの作業はエージェントの
分担。毎朝の定期実行にするには `news-digest/references/scheduled-operation.md`。

## 必要なもの

Python 3.11 以降、それだけ。スクリプトは標準ライブラリのみを使う。
パッケージのインストールも、常駐サービスも、データベースも要らない。
フィード収集に資格情報は不要で、トークンが要るソースは実値ではなく
環境変数名を参照する。

ダイジェストの送信は、実行時にエージェントが使える送信ツールを用いる。
設定が宣言するのは**宛先**であって経路ではないので、特定のローカル CLI にも
特定の MCP サーバにも依存しない。適当なツールが無ければ、実行は完走してその旨を報告する。

## やらないこと

Web UI は持たない。本文の全文アーカイブもしない（必読と判定したものの要約だけを残す）。
登録したフィードと自分が読むと決めた記事の外へはクロールしない。フィードと記事本文は
一貫して非信頼データとして扱い、記事テキストはノンス付きタグに包まれた状態で
エージェントに届く。記事の中に現れた URL は取得しない。

## 開発

```bash
make check      # 構造検証（= make test）
make install    # ~/.claude/skills/news-digest へコピー
make package    # dist/news-digest-vX.Y.Z.zip を作る
```

設計記録は `docs/ja/adr/`（英語版は `docs/en/adr/`）。
